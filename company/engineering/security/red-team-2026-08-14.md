### CRITICAL

#### RT-SEC-01 — RLS is `allow all` for anon on every table (Critical)

- **Repro:** With `anon` key, `POST /rest/v1/polls` or `poll_options` or `votes` or `events` with any payload succeeds. There is no row-owner check; anon can `UPDATE polls SET title='pwned'` or `DELETE FROM votes`. `supabase-js` `supaAnon()` (`lib/supabase.ts:10-16`) is shipped to browsers with `NEXT_PUBLIC_SUPABASE_URL/_ANON_KEY` — anyone can extract the key and call the PostgREST endpoint directly, bypassing all `lib/store.ts` validation. RLS is enabled but policy is `using (true) with check (true)` for all four tables.
- **Evidence:** `app/supabase/migrations/001_init.sql:66-80` `create policy "allow all ..."` on `polls`, `poll_options`, `votes`, `events`; comment `MVP is anon-friendly; ... allow anon read/write via anon key`. `lib/supabase.ts:12-15` ships anon key to client. No `authenticated` role distinction.
- **Fix:** Keep RLS enabled but tighten before prod: `polls/poll_options` — anon `SELECT` yes, `INSERT` only with `title`/`label` checks (e.g. `char_length` already in DB) and rate window; `votes` — anon `INSERT` only if `poll_id` exists and dedup `not exists`; `events` — anon `INSERT` only, never `SELECT/UPDATE/DELETE`. Serve all writes through API routes using `service_role` (`lib/store.ts:176-192` already does) and revoke direct anon writes (drop `allow all`, add API-only policies or disable PostgREST anon write and rely on service_role only). Rotate anon key after tightening.

#### RT-SEC-02 — Rate limits are absent or trivially bypassable in prod path (Critical)

- **Repro A — poll spam:** `store.ts` Supabase branch has no create rate limit (mock 5/hr, prod 0). Script `for i in 1..1000; do curl -X POST /api/polls -d '{"title":"spam …"}'` → 1000 polls created, no 429. Events/polls/votes tables bloat, search/SEO poisoned.
- **Repro B — vote spam:** Supabase vote limit counts existing `votes` rows by `ip_hash` (`store.ts:318`), but attacker rotates `x-forwarded-for` or `x-real-ip` (see RT-SEC-04) to rotate `ip_hash`, clearing the counter. Also mock rate stored in `Map` is per-process — Vercel serverless functions each have their own `globalThis.__pollpop_mock` → rate is not shared across invocations so mock rate is absent in prod mock fallback too.
- **Evidence:** `app/lib/store.ts:140-148` create rate only in `!isSupabaseConfigured`; `175-192` Supabase create none; `206-322` vote rate per `ip_hash` only in prod (bypassable). `dedup.ts:59-64` `clientIpFromHeaders` trusts first `x-forwarded-for`.
- **Fix:** Add middleware rate limit (Vercel `rateLimit` or Upstash Redis) for `POST /api/polls` (5/min/IP + 20/day/cookie) and `POST /api/polls/:id/vote` (10/poll/24h/IP) + `POST /api/events` (60/min/IP). Trust `x-forwarded-for` only from Vercel trusted proxy (Vercel sets `x-vercel-forwarded-for`/`x-real-ip`) — or use `req.ip` from platform. Persist limits in DB/Redis, not `Map`.

### HIGH

#### RT-SEC-03 — `IP_HASH_SALT` falls back to `"dev-salt"` — IP hashes are reversible with a known salt (High)

- **Repro:** Deploy without `IP_HASH_SALT` env (easy to miss — `NEXT_PUBLIC_*` vars are documented but `IP_HASH_SALT` is not in `.env.example`). All voter's `ip_hash = sha256(ip + "dev-salt")`. Known-plaintext dictionary of IPv4 (4B) + this salt is cheap offline → `ip_hash` column deanonymizes to real IPs. Privacy claim ("Raw IP never stored — only ip_hash" — `app/metrics/page.tsx:100`) is broken if salt is default.
- **Evidence:** `app/lib/store.ts:177,223,313` `process.env.IP_HASH_SALT || "dev-salt"`; `supabase.ts:20-22` same pattern in `supaService()` connection; no startup check enforces `IP_HASH_SALT`.
- **Fix:** Fail hard at boot if `IP_HASH_SALT` missing in non-dev (`NODE_ENV=production → throw`). Generate salt with `openssl rand -hex 32` and store in Vercel env + Supabase env. Document in `DEPLOY.md` and `.env.example`. Consider `HMAC-SHA256(salt, ip)` with per-quarter rotation + `salt_version` column rather than `hash(ip+salt)`.

#### RT-SEC-04 — `clientIpFromHeaders` blindly trusts `x-forwarded-for` first entry — IP spoof (High)

- **Repro:** `curl -H "x-forwarded-for: 1.1.1.1, 2.2.2.2" POST /api/polls` → `dedup.ts:61` picks `1.1.1.1` as client IP regardless of which proxy actually set the header. Attacker sets any IP to poison `ip_hash` attribution, bypass vote rate limits, or impersonate creator attribution.
- **Evidence:** `app/lib/dedup.ts:59-65` no trusted-proxy check; `app/app/api/polls/route.ts:26`, `app/app/api/polls/[id]/vote/route.ts:23` both call it for billing/rate decisions.
- **Fix:** On Vercel, trust `x-vercel-forwarded-for` or `req.ip` from `next/server` (or `request.ip` if behind Vercel). If manually trusting `x-forwarded-for`, take the last entry (closest to server) or validate against known proxy CIDRs. Never trust a header the client can set for dedup/security.

#### RT-SEC-05 — Cookie is JS-readable (`httpOnly false`) and also accepted via `x-pollpop-cid` header — session fixation / dedup takeover (High)

- **Repro:** `dedup.ts:27` sets cookie `SameSite=Lax` without `HttpOnly`, `Secure`. Any XSS (even a stored label if later reflected) can read `document.cookie` and clone `pollpop_cid`. `vote/route.ts:16` then trusts `x-pollpop-cid` header as equal to cookie — attacker can set any dedup key per request.
- **Evidence:** `app/lib/dedup.ts:27` `document.cookie = ... Max-Age=31536000; SameSite=Lax` no `HttpOnly; Secure`; `app/app/api/polls/[id]/vote/route.ts:14-16`, `app/app/api/polls/route.ts:24-25` `x-pollpop-cid` accepted.
- **Fix:** Set cookie server-side (`set-cookie` in `vote/route.ts:21,34` and a dedicated `/api/session` or middleware) with `HttpOnly; Secure; SameSite=Lax`. Keep `x-pollpop-cid` only as fallback for clients that block `Set-Cookie` (e.g. strict ITP), and on first receipt, rotate to a `Set-Cookie` so later requests come via cookie. Document soft-identity model.

#### RT-SEC-06 — Request bodies are unbounded (`image_url` data URLs, `meta` JSON) — DoS / DB bloat (High)

- **Repro:** `POST /api/polls` with 4 × 6 MB data URLs (≈26 MB JSON) → stored as `text` in `poll_options.image_url`; `POST /api/events` with `meta: {a: "x".repeat(2_000_000)}` → stored as `jsonb`. No `body` size guard in any API route. Next.js default body limit (~4 MB) may reject some but is not explicitly set, and Vercel function payload limits are high enough to still bloat `polls`/`events`.
- **Evidence:** `app/app/api/polls/route.ts:8-19` raw `req.json()` no size check; `app/components/CreateForm.tsx:32-37` data URL as image_url; `app/app/api/events/route.ts:19` meta unbounded; `app/supabase/migrations/001_init.sql:23,56` `image_url text`, `meta jsonb` no check.
- **Fix:** Set `export const config = { api: { bodyParser: { sizeLimit: '512kb' } } }` or Next middleware guard; reject data URLs server-side (require `https://` with allowlist or Storage URL), enforce `octet_length(image_url) < 2048` in DB. Cap `meta` to 2 KB serialized (RT-BUG-19).

#### RT-SEC-07 — `/api/events` accepts arbitrary `poll_id` and `ref` — metrics poisoning + silent FK violation (High)

- **Repro:** `curl /api/events -d '{"name":"poll_create_complete","poll_id":"nonexistent","ref":"poll_victim"}'` → `recordEvent` inserts row (`store.ts:359-368` `supa.from("events").insert(row)`) even though `poll_id` FK is `on delete set null` but should be validated. Attacker can emit arbitrary `poll_view`/`cta_click`/`vote` events for any poll to inflate CTR, K-factor, voters_per_poll on `/metrics`. `ref` is only sliced to 120, not validated against existing `polls.id` when counting `via_cta`.
- **Evidence:** `app/app/api/events/route.ts:12-23` no `poll_id` existence check; `app/lib/store.ts:383,438-446` counts `via_cta` as `ref.startsWith("poll_")` regardless of poll existence.
- **Fix:** Validate `poll_id` exists before insert (or insert with `null` if FK fails, don't attribute). Count `via_cta` only when `ref` equals `poll_{existing_id}`. Add anon `events` RLS `INSERT` policy that allows insert but requires `name` in allowlist (already enforced in route) and `poll_id` either null or exists. Consider signing `ref` attribution server-side.

#### RT-SEC-08 — OG SVG is served without CSP / X-Content-Type-Options — SVG script vector if escape ever missed (High)

- **Repro:** If `escapeXml` ever misses a vector (e.g. future change adds `'` or template injection in `blocks` `colors[i]`), `image/svg+xml` served from same origin can run script when opened directly. Today `escapeXml` only replaces `& < > "` (`og/route.ts:28`). No `Content-Security-Policy` or `X-Content-Type-Options: nosniff` on OG response.
- **Evidence:** `app/app/api/polls/[id]/og/route.ts:27-29,81-87` SVG generation; headers only `content-type`, `cache-control`, `x-pollpop-og`.
- **Fix:** Add `content-security-policy: default-src 'none'` + `x-content-type-options: nosniff` on OG. Expand `escapeXml` to include `'` → `&#39;` and validate `colors` against `^#[0-9a-f]{6}$`.

### MEDIUM

#### RT-SEC-09 — Profanity / NSFW only covers title, not context/label/image — content moderation gap (Medium)

- **Repro:** See RT-BUG-11. NSFW image has no detection; five-word profanity list (`\bfuck\b|\bshit\b|\bnigger\b|\bporn\b|\bxxx\b` `store.ts:137`) easily bypassed with leet/spaces/unicode. Polls are public and shareable, link unfurls externally — reputational risk.
- **Evidence:** `app/lib/store.ts:137-138` title-only, hardcoded list; `components/CreateForm.tsx` no image check; `001_init.sql:12` `status check (active,flagged,removed)` exists but no code ever sets `flagged`.
- **Fix:** Expand filter to context/label, use a maintained list or `better-profanity` style wordlist. Add async Storage + `status='flagged'` path gated by image hash / Cloud Vision tier-2.

#### RT-SEC-10 — `NEXT_PUBLIC` Supabase anon key is shipped to client — expected, but direct PostgREST bypasses API validation (Medium)

- **Repro:** Extract `NEXT_PUBLIC_SUPABASE_ANON_KEY` from page JS, call `https://{project}.supabase.co/rest/v1/polls` to insert a poll with 1 or 5 options, title>80, etc. — bypasses `store.ts` validation entirely because RLS allow-all (RT-SEC-01). Same for votes with arbitrary `voter_cookie`/`ip_hash`.
- **Evidence:** `lib/supabase.ts:4-16` `NEXT_PUBLIC_*` + `supaAnon()`; `001_init.sql:66-80` allow-all. This is already RT-SEC-01 root cause, listed separately here for tracking.
- **Fix:** Same as RT-SEC-01: disable anon write, go through API + service_role; or add DB `CHECK` constraints (already present for `title`/`label` length) but still need rate/dedup checks. Rotate key after.

#### RT-SEC-11 — Data URLs persisted unsanitized — stored XSS / content-type confusion (Medium)

- **Evidence:** `components/CreateForm.tsx:32-37` data URL; `lib/store.ts:134` validates `new URL(image_url)` — `data:text/html;base64,...` passes `new URL` but is not an image. Later rendered as `<img src={o.image_url}>` (`VoteGrid.tsx:32`) — browser will try to render HTML as image (usually safe) but OG and future Storage paths could be confused. `poll_options.image_url` accepts `data:` scheme.
- **Fix:** Allow only `https:` URLs matching `remotePatterns` or `data:image/(png|jpeg|webp);base64,` (block `data:text/html`). Prefer Storage URLs only.

#### RT-SEC-12 — `500` responses leak Supabase / Postgres detail (Medium)

- **Evidence:** `app/app/api/polls/route.ts:42` `pErr.message` returned, `app/app/api/polls/[id]/vote/route.ts:37` `e.message`, `app/app/api/events/route.ts:26` `e.message`. See RT-BUG-10.
- **Fix:** Map to generic 500; log detail server-side with `console.error`.

#### RT-SEC-13 — No validation that `ref` attribution corresponds to a real poll — viral metric inflation (Medium)

- **Duplicate of RT-SEC-07 K-factor slice:** Counts `via_cta` as `ref.startsWith("poll_")` (`store.ts:383`). Fix: validate `ref` against `polls.id` before counting.

### LOW

#### RT-SEC-14 — No request signing / CSRF for state-changing POSTs (Low)

- `/api/polls` and `/api/polls/:id/vote` rely only on cookie; no `Origin`/`Referer` check, no double-submit token. Vercel's same-site defaults plus `SameSite=Lax` mitigate CSRF for cookie path but `x-pollpop-cid` header path is not protected. Low because voting via CSRF has limited impact (poll spam).
- **Fix:** Check `Origin` allowlist in API routes; require `content-type: application/json` (already) which browsers preflight.

#### RT-SEC-15 — Secrets handling — `SUPABASE_SERVICE_ROLE_KEY` must never be `NEXT_PUBLIC` (Low — correct today)

- **Evidence:** `lib/supabase.ts:19-23` `SUPABASE_SERVICE_ROLE_KEY` is server-only (correct). No client import of `supabase-admin.ts`. No `.env` committed (`.gitignore` covers it). Passing today, kept as regression guard.
- **Fix:** None; add CI check `grep -r SUPABASE_SERVICE_ROLE_KEY app/components`.

#### RT-SEC-16 — `.pollpop-mock.json` is gitignored (good) but file fallback swallows errors silently (Low)

- **Evidence:** `.gitignore` lists `app/.pollpop-mock.json`, `.pollpop-mock.json` (good). `store.ts:43-59` all `catch {}` swallow `require("fs")` failures. In Vercel serverless (read-only fs), writes silently no-op; local dev may think data persisted when it didn't.
- **Fix:** Log `persistMock` failures with `console.warn` in non-prod, and document that mock mode is ephemeral on serverless.
